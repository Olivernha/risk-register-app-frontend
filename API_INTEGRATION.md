# Risk Register - Dynamic API Integration Summary

## ✅ Completed Setup

### 1. JSON Server Configuration
- **Port**: 3000
- **Database**: `db.json`
- **Auto-save**: Enabled (read-only: false)
- **CORS**: Enabled
- **Watch mode**: Active

### 2. API Integration
- **Base URL**: `http://localhost:3000`
- **Endpoints**:
  - GET `/risks` - List all risks
  - GET `/risks/:id` - Get single risk
  - POST `/risks` - Create new risk
  - PATCH `/risks/:id` - Update risk
  - DELETE `/risks/:id` - Delete risk

### 3. Data Persistence
When you create a new risk:
1. Frontend sends POST request to `http://localhost:3000/risks`
2. json-server automatically saves it to `db.json`
3. The new risk appears immediately in the list
4. **File is updated automatically** - no manual save needed

### 4. Sample Data
Current `db.json` contains:
- 3 sample risks (R1, R2, R3)
- 2 versions (2025 Q4 Active, 2025 Q3 Locked)
- Sample users
- Heat map matrix data

## 🔍 Troubleshooting

**Risk not appearing after create:**
- Check browser console for errors
- Check Network tab for POST request to `/risks`
- Verify json-server is running (check terminal)
- Look at `db.json` to see if it was added

**json-server not saving:**
- Restart json-server: `bun run server`
- Check file permissions on `db.json`
- Verify `json-server.json` has `"read-only": false`

**Changes lost after refresh:**
- This shouldn't happen - json-server persists to disk
- If it does, check if db.json is being overwritten
